# v0.2 roadmap

Status: implementation complete; review and release tag pending

## Release intent

Version 0.2 makes the UI foundation testable and ready for incremental adoption.
It describes repeatable behavior and provides visual references without
introducing a framework or a shared component package.

## In scope

- Harden semantic tokens for interaction, forms, layout, and layering.
- Define font loading and mixed-script typography behavior.
- Demonstrate representative controls, states, AI provenance, and responsive
  layouts in the living preview.
- Add accessibility, migration, and visual-review checklists.
- Define how products share a family resemblance while retaining individuality.
- Add dependency-free validation for token references and critical contrast
  pairs.

## Explicitly out of scope

- Changes in Task Queue or any consuming application.
- Authentication and user-management interfaces.
- Dark mode.
- React, Tailwind, native, JSON, or TypeScript token packages.
- npm publishing or a Figma library.
- Production-ready shared components.
- Final colors or logos for applications that have not yet been designed.
- The reusable AI Bharatiyaa UI skill.

## Release criteria

Version 0.2 is ready to tag when:

1. The automated validator passes.
2. The preview has no horizontal page overflow at the four review widths.
3. All preview controls have accessible names and visible keyboard focus.
4. Motion remains understandable when reduced motion is requested.
5. Critical normal-text pairs meet WCAG 2.2 AA contrast.
6. Documentation does not instruct consumers to adopt unreleased packages.
7. Deferred work is visible in this roadmap or the changelog.

## Compatibility and versioning

Applications should pin a commit or release tag rather than linking to the
default branch. Additive tokens and documentation clarifications are compatible
within a minor release. Removing or renaming a token is breaking and requires:

1. A replacement token.
2. A migration example.
3. A deprecation period spanning at least one minor release.

The first consuming applications may copy `tokens.css` while the contract is
young. Package distribution should be introduced only when two applications
need the same delivery mechanism.
